## Высокая важность

### 1. Бэкап мог молча сохранить пустую базу

`ansible/roles/backup/templates/homelab-backup.sh.j2`

Функция `backup_app` вызывалась как `backup_app ... || failed=1`. В таком
контексте bash отключает `set -e` внутри функции, и ошибки команд не
прерывали её. Если `sqlite3 .backup` падал, например база была занята,
следующая проверка целостности открывала несуществующий файл копии. sqlite3
создавал на его месте пустую базу, проверка пустой базы возвращала `ok`, и в
архив уходила пустая база с отметкой об успехе. То же случилось бы при
переименовании базы: sqlite3 создал бы пустой файл прямо в `data`.

**Исправлено.** Каждая команда проверяется явно. До копирования проверяется,
что база существует и не пуста, после копирования проверяется, что копия не
пуста. Проверка целостности открывает копию только на чтение. Проверено на
сервере на трёх случаях: нормальная база, отсутствующая база и отсутствующий
каталог данных.

### 2. `--diff` печатал секреты из env-файлов

`ansible/roles/compose_app/tasks/main.yml`

README велит запускать Ansible с `--diff`. При любом изменении env-файла
Ansible показывал его diff вместе с `BOT_TOKEN`, `TP_TOKEN` и хешем админки,
и секреты оставались в истории терминала.

**Исправлено.** У задачи с env-шаблоном стоит `diff: false`.

## Средняя важность

### 3. Пароль Vault был только на ПК

Если бы ПК умер, `vault.yml` было бы не расшифровать, и восстановить сервер
из репозитория не получилось бы.

**Исправлено.** Пароль сохранён в менеджере паролей.

### 4. Стойкость пароля Vault в публичном репозитории

Файл пароля занимал 14 байт, это около 13 символов. Зашифрованный
`vault.yml` лежит в открытом доступе, и пароль можно перебирать офлайн без
ограничений. Для случайного пароля такой длины это не страшно, для слова
или фразы опасно.

**Исправлено.** Пароль заменён на случайный из 32 символов и сохранён в
менеджере паролей.

Как менять пароль в будущем. `ansible-vault rekey` берёт новый пароль из
`vault_password_file` в `ansible.cfg` и ничего не спрашивает, поэтому
запускать его нужно без проектного конфига. Файл пароля записывать только
через `read` и `printf`: `echo` в двойных кавычках исказит пароль с `!`,
а лишний пробел в конце сломает расшифровку.

```sh
cd /mnt/d/my_projects/homelab/ansible
env -u ANSIBLE_CONFIG ansible-vault rekey inventory/group_vars/all/vault.yml
read -rs NEWPASS && printf '%s' "$NEWPASS" > .ansible-vault-pass && unset NEWPASS
ansible-vault view inventory/group_vars/all/vault.yml > /dev/null && echo ok
```

После смены обновить пароль в менеджере паролей. Старые версии `vault.yml`
в истории git остаются зашифрованными старым паролем.

### 5. find-air собирается из плавающего `master`

`services/apps/find-air/docker-compose.yaml`

Каждая пересборка берёт то, что сейчас лежит в ветке, поэтому развёртывание
не воспроизводится: одна и та же версия репозитория homelab может дать
разный код бота.

**Предложение.** Указать в контексте сборки тег или коммит вместо `master`.

### 6. Базовый образ find-air не обновляется

`ansible/roles/compose_app/tasks/main.yml`

Для приложений со сборкой стоит `pull: never`, а Compose при сборке не
скачивает свежий базовый образ `python:3.12-slim`. Обновления безопасности
базового образа не придут никогда.

**Предложение.** При пересборке скачивать свежий базовый образ, например
через `build.pull: true` в compose.

### 7. Удаление сервиса не останавливает его на сервере

Корневой README обещает: удаляешь сервис, удаляешь папку целиком. Но если
убрать приложение из `apps`, Ansible про него просто забудет, контейнер
продолжит работать, а каталог в `/opt` останется.

**Предложение.** Список удаляемых приложений, по аналогии с
`nginx_sites_absent` у nginx: остановить проект и убрать каталог, оставив
последний бэкап.

### 8. Любой домен на 443 попадает в vaultwarden

`services/network/nginx/sites-available/`

Заглушка `default` слушает только порт 80. На 443 единственный сайт это
vaultwarden, поэтому ему достаются все запросы по IP и с чужими доменами,
включая сканеры.

**Предложение.** Добавить заглушку на 443 с `default_server` и
`ssl_reject_handshake on`.

- Корневой README, в начале: «и, позже, Ansible», хотя Ansible уже есть.
- Корневой README, таблица сервера: «на базе Debian», а на сервере Ubuntu

- Корневой README, таблица сервера: «статический адрес», а ниже верно

- README nginx: раздел «Применить изменения руками» предлагает `cp` в обход

- `ansible/vault.example.yml`: комментарий требует одинарных кавычек, а
  значение в двойных.

### 10. Двойное задание `DB_PATH` у find-air

В env-шаблоне `data/findair.db`, в compose `/app/data/findair.db`.
Побеждает compose, значение из шаблона только сбивает с толку.

### 11. `server_tokens build` раскрывает сборку nginx

`services/network/nginx/nginx.conf`. Комментарий в самом файле советует
`off`.

### 12. Повторный запуск файрвола может споткнуться

`ansible/roles/firewall/tasks/main.yml`

Если таймер отката однажды сработает с ошибкой, systemd оставит юнит
`homelab-firewall-revert` в состоянии failed. Следующий `systemd-run` с тем
же именем откажется его создавать, и применение правил упадёт.

**Предложение.** `systemctl reset-failed homelab-firewall-revert.service`
перед `systemd-run`.

### 13. Docker не обновляется автоматически

unattended-upgrades берёт только репозитории Ubuntu, а Docker CE стоит из
стороннего репозитория. Обновлять его придётся вручную или добавить его
источник в настройки unattended-upgrades.

### 14. Бэкапы не зашифрованы

В архиве vaultwarden лежат база и `rsa_key.pem`. Пока архивы на сервере с
правами `600`, это нормально. При отправке в Google Диск нужно шифрование,
например `rclone crypt`.

## Что хорошо

- Секреты не попадали в git ни в одном коммите.
- Опасные операции защищены: `nginx -t` и `sshd -t` перед reload, откат
  файрвола по таймеру, проверка каталога `data` в роли приложений.
- Правила Docker не страдают ни при применении файрвола, ни при загрузке.
- Проверка всего `site.yml` даёт ноль изменений, роли идемпотентны.
